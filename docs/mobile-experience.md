# 手机端体验与验收

本次主要修复真正的遮挡、裁切和输入问题，不通过全局 `overflow-x: hidden` 掩盖内容溢出。

## 修复点

- **外观面板**：原来的 `position: fixed` 子元素被带 `backdrop-filter` 的顶栏变成相对顶栏定位，手机上只露出面板底部。改用原生 `dialog` 顶层，手机显示可滚动的底部面板，关闭按钮固定可见，支持 Esc、背景点击、焦点恢复。桌面仍为右上方外观面板。
- **统计图表**：移除依赖 500px 最小宽度的裁切布局。图表根据容器宽度重新计算柱、点和标签，不把整张 SVG 缩成难读的小字；首尾时间标签保留。提供可展开的数据表，触屏不必依赖鼠标悬停查看数值。
- **键盘与助手**：VisualViewport 仅同步尺寸到 CSS 变量，不接管页面滚动或缩放。手机助手为模态面板，输入与发送按钮避开软键盘；打开时不强制聚焦输入。手机回车换行，显式发送按钮发送，中文输入法确认键不误发消息。桌面继续使用不阻塞阅读的侧边助手。
- **后台编辑器**：AI 调整范围选择框不再撑宽 320px 屏幕；字号至少 16px，避免 iOS 自动放大。专注模式跟随可视区域，工具栏可以横向滑动，退出按钮不被键盘挤走，源文本保持不变。
- **阅读和点击区域**：手机首页收紧装饰区，提高摘要字号；顶栏和主要按钮保留约 44px 点击区域。文章目录改为正文前的行内折叠目录，避免吸顶后盖住正文标题。音乐默认折叠，展开时避开阅读进度；手机写作台不再叠加第二个全局 AI 浮钮。

## 检查命令

```bash
npm run check
npm test
BASE_URL=http://127.0.0.1:3100 npm run test:mobile
```

浏览器检查使用现有管理员记录签发内存中的短期会话，不打印令牌，不保存文章、不发 AI 请求。音乐控件使用测试上下文内的模拟曲目响应，不写入站点音乐设置。

覆盖 320 / 360 / 390 / 430px 竖屏、844px 横屏、前后台页面、弹窗内滚动、焦点恢复、图表边界、中文 IME、键盘可视区域及桌面回归。检测页面宽度时与真实设备视口比较，而非只比较 `scrollWidth` / `innerWidth`——手机浏览器可能把两者一起放大，从而让溢出检查产生假阴性。

软键盘检查通过模拟 VisualViewport 缩小与偏移验证布局，**不等同于所有真实 iPhone / Android 浏览器的实机测试**。默认截图保存在 `/tmp/shibei-mobile-ui`，可以通过 `MOBILE_UI_ARTIFACTS_DIR` 指定目录。
